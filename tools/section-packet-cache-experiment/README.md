# H8 section and packet-body cache experiment

This standalone workspace uses only existing local crates and changes no production consumer. Run from the isolated hardening checkout:

```powershell
python tools/section-packet-cache-experiment/run.py --correctness-only
python tools/section-packet-cache-experiment/run.py
```

Coordinate the second command with other benchmark work. It builds a new release executable in a unique evidence directory, runs ten Rust regressions, strict prototype formatting/clippy, four existing Windows Job process controls, eighteen Java 8 differential fixtures and a deliberately corrupted first-byte control. Only then does it run one warmup and five measured repetitions of forty cases. Raw stdout/stderr, all failures and before/after source/tool hashes remain in `target/architecture-hardening/h8-section-packet-cache-*`.

## What is encoded

The complete unframed protocol-340 chunk packet body is packet ID 0x20, signed x/z, ground-up Boolean, mask VarInt, payload-length VarInt, selected sections, optional 256-byte biome array and an empty block-entity list. Framing, compression, encryption, nonempty block entities, packet submission and actual Minecraft/Forge state are outside this prototype. Protocol 338 is explicitly rejected. Direct palette width is fixed to the admitted 13-bit fixture domain; the legacy global setting is checked when constructing legacy state and never changed. Runtime IDs start at 70000 and must resolve through an explicit map to wire IDs below 8192. Missing mappings/sections, unsupported rules and insufficient capacity return errors.

The existing `native-chunk` encoder supplies a mask/byte-count result from its serialization. The independent experimental packer traverses frozen H6 `NativeSection` public APIs. Both produce a private, immutable `Encoded` record binding key, emitted mask and body bytes. The Java oracle uses a separate bit-by-bit implementation, rather than Rust's word-spill algorithm, and compares every body byte. Its input is generated semantic fixture data, not a Forge snapshot. The pinned PrismarineJS schema independently establishes the envelope and packet ID; the local legacy encoder establishes the exact section domain. Fixtures cover local widths 4–8, the 255/256 non-air direct transition, 13-bit direct IDs, air, sparse/all/empty selections, partial data, sky/no sky, recipient transformation and changed state/light/biome data.

## Cache contract and bounds

Keys include session, world/chunk, incarnation, lifecycle/owner, registry epoch, state/light/biome generations, protocol, dimension and recipient rule identities, mask, sky and full/partial flags. `publish` compares the returned encode key/mask with the supplied current key before adoption. The serial harness is the trusted owner of that current key and of generation updates. Public fixture fields make this an experiment, not a capability-safe engine API: callers can lie about current identity or mutate inputs without bumping generations. Integration must obtain the key and snapshot from H6's validated publish path under the ownership boundary. No runtime lifecycle or JVM fence is implemented here.

Resident payload budgets are 64 or 512 KiB; unique adopted live payload budgets are 96 or 768 KiB. Entries are immutable `Arc` bodies. A drop hook counts unique adopted bytes until the last reader releases them, even after eviction/invalidation. Admission uses least-recently-used eviction; if old readers still fill the live budget, it returns the owned pending encode result and requires a consumer to drain before retry. There is no success-shaped dropped packet or unbounded fallback. A serialized producer has at most one pending encode result in this harness; it is not charged to the adopted-body budget. Concurrent producers would need a separate reservation budget.

This is a payload-byte budget, not total allocator/RSS accounting. It excludes keys/tree nodes/Arc headers, H6 input state, mapping trees, private legacy palettes, scratch vectors and the pending encoded body. Native/Java runtime children additionally have a 512 MiB Windows process-commit limit, a one-process Job, a bounded output prefix and deadlines. Cargo/build tools have bounded waits and process-tree cleanup on timeout, not that memory limit. The shared Job helper's four controls check assignment/resume failures, output overflow and a child that closes pipes but keeps running. Tool provenance does not cover every linker/SDK/system binary or host setting.

## Timing boundaries and fairness

Section cases are uniform, eight-state local palette, 64-state local palette, forced DenseHot with eight states and 1024-state DenseHot/direct wire. Each performs 100000 reads and 10000 prepared writes with section references acquired before timing. The same spatial operations use explicit corresponding u16 wire or u32 runtime identities; full state parity is checked outside the timer. Setter workloads may contain no-ops, especially uniform; lookup-specific tests separately force every write to change a state. Warm legacy packing retains its existing palette/packed-word cache. Cold legacy packing invalidates that cache before each timer, outside the measured interval. Experimental body packing performs runtime mapping, palette construction and word packing each time. Sixteen complete body encodes include output allocations, envelope and checksum work. This is intentionally a comparison of current end-to-end APIs, not an isolated word-packer claim.

The lookup experiment compares H6 linear-only and hash-backed palettes at cardinalities 8 and 64, with 32768 changed writes per variant. Construction is outside the timer; every resulting state is checked. Alternate run order reduces a fixed ordering bias. It does not tune a universal threshold. Transition timings include 64 writes that cause hot promotion, and 4096 writes plus three maintenance sweeps that demote to uniform; they are not pure transition-instruction costs.

Cache workloads have one or sixteen synthetic recipients, overlapping square views of radius 2 or 8 (25 or 289 single-section chunks), two complete delivery rounds, and zero or one mutation per chunk per round. Recipient rules alternate between identity and a simple non-air masking rule. High mutation means 100% of chunks changed, not 100% of cells. At each chunk, all recipients are served consecutively; this deliberately measures immediate fan-out sharing. It does not model a network or general scheduler. Slow consumers retain every player-zero body until a 64-entry queue or the live budget requires draining. Both paths use the same pending-consumer cap. Producer backpressure is represented by immediate release of the oldest pending reader, not simulated network delay. Timers exclude world/legacy construction and include actual setter/invalidation, lookup/admission/eviction and delivery checksum/length accounting. Uncached mutation updates existing dense sections; it does not rebuild entire chunks. A cache hit reuses the stored digest, which is an additional avoided per-body computation. No actual socket send or per-recipient byte copy is timed.

The workload asserts delivered byte count and accumulated body checksum parity; this is not cryptographic or independent per-request byte equality. Full byte equality is established by the separate eighteen fixtures and Rust regressions. Output retains min/median/max of five measured samples, plus raw warmup; no percentile, statistical significance or real-server speedup is claimed. HashMap random seeds, shared-host scheduling, CPU frequency and small wall-clock intervals add noise. The Job monitor polls while the runtime child executes.

Memory columns report legacy whole-section inline size and experimental section wrapper inline size (both include 4096 light bytes), plus H6 vector payload capacities and hash-table capacity in entries. Uniform's state is already inline and therefore has zero dynamic vector bytes. Legacy private cached-palette allocations and actual HashMap bucket bytes cannot be observed through the reused public API; those costs remain explicitly unmeasured. These columns must not be presented as total-memory comparisons.

`provenance.json` pins Valence/Hyperion studied implementations and the protocol schema. Valence's mutation-invalidated packet cache and Hyperion's palette/channel proposal inform the experiment; no upstream implementation is copied or installed. The Hyperion issue is a proposal, not shipped-performance evidence. Their relevant notices are retained. Nothing here enables native packet authority or resolves live snapshot coherency.
