# ChunkDataEvent.Save Compatibility & NBT Bypass Hazard Analysis

## 1. Architectural Problem Definition

In Task P0-3, isolating chunk saving to a background Rust thread was identified as a candidate optimization for eliminating steady-state tick spikes.
However, in Minecraft Forge 14.23.5.x, chunk saving is not an isolated engine operation: it interacts directly with mod event subscribers through `net.minecraftforge.event.world.ChunkDataEvent.Save`.

---

## 2. Forge Save Sequence & Call Order

Tracing `AnvilChunkLoader.saveChunk(World, Chunk)`:

```java
NBTTagCompound rootCompound = new NBTTagCompound();
NBTTagCompound levelCompound = new NBTTagCompound();
rootCompound.setTag("Level", levelCompound);
rootCompound.setInteger("DataVersion", 1343);
FMLCommonHandler.instance().getDataFixer().writeVersionData(rootCompound);

// 1. Synchronously populate vanilla chunk NBT
this.writeChunkToNBT(chunk, worldIn, levelCompound);

// 2. Synchronously write Forge chunk tickets (forced chunks)
ForgeChunkManager.storeChunkNBT(chunk, levelCompound);

// 3. Post ChunkDataEvent.Save on Forge EVENT_BUS
MinecraftForge.EVENT_BUS.post(new ChunkDataEvent.Save(chunk, rootCompound));

// 4. Queue completed compound for async disk writing
this.addChunkToPending(chunk.getPos(), rootCompound);
```

### Critical Flow Observations:
1. `ChunkDataEvent.Save` receives `rootCompound`, which contains the fully populated `Level` compound (including `Sections`, `Entities`, `TileEntities`, `Biomes`, `HeightMap`, `TileTicks`).
2. The event is fired on the **Server thread** immediately before `addChunkToPending` pushes the compound to the background IO queue.
3. The event is **not cancelable**, but the `NBTTagCompound` handed to mods via `event.getData()` is **fully mutable**.

## 3. Real-World Forge Mod Usage Patterns

A search across popular Forge 1.12.2 mod source repositories reveals three primary categories of `ChunkDataEvent.Save` usage:

| Mod Category | Examples | Observed Behavior in Event Handler | Compatibility Impact if Bypassed |
| :--- | :--- | :--- | :--- |
| **Custom Chunk State Persistence** | Astral Sorcery, Advanced Rocketry, Galacticraft | Injects custom compound into `event.getData()`: e.g. `event.getData().setTag("astralsorcery", data)` | **Total Data Loss:** Mod state permanently vanishes on world reload. |
| **Dungeon & Structure Markers** | Roguelike Dungeons, Twilight Forest, Recurrent Complex | Reads coordinates and flags whether structure generation was completed | **Regeneration Bugs:** Structures re-generate or cascade endlessly. |
| **Server Frameworks & Plugins** | SpongeForge, ForgeEssentials | Injects custom claims, permissions, and chunk ownership tags | **Security & Permission Failure:** Claimed regions lose protections. |

## 4. The Blind Bypass Failure Mode

If a Rust runtime attempts to bypass Java chunk saving by serializing chunk terrain and entities directly from native memory to `.mca` files without executing `saveChunk` on Java:

```
[NAIVE BYPASS ATTEMPT]
Rust Background Saver ────> Directly writes .mca sector ────> DISK
                                   ▲
                             MISSING LINK:
             Forge EventBus NEVER posts ChunkDataEvent.Save!
           All mod-injected custom NBT compounds are lost!
```

### Consequences:
1. Mods listening to `ChunkDataEvent.Save` never have their handlers invoked.
2. If the event is fired with an empty synthetic compound, mods that read `Level` crash with `NullPointerException` or corrupt their logic.
3. If mods attach tags to the synthetic compound, those tags are lost unless explicitly merged into the final Rust stream.

---

## 5. Architectural Recommendation: The Hybrid Event Merge Seam

To maintain 100% Forge mod compatibility while optimizing chunk save performance:

1. **Lightweight Event Compound:**
   The Java bridge constructs a minimal root compound containing `Level` with basic coordinates (`xPos`, `zPos`, `DataVersion`), capabilities (`ForgeCaps`), and empty collections.
2. **Post Event on Server Thread:**
   `MinecraftForge.EVENT_BUS.post(new ChunkDataEvent.Save(chunk, eventCompound))` is dispatched on the Server thread as required by Forge invariants.
3. **Rust Tag Extraction & Merge:**
   Any additional tags injected by mods into `eventCompound` are extracted via `NbtCursor` and merged into the binary chunk payload generated by Rust before final ZLIB compression and disk sector writing.
