# Minecraft 1.12.2 Mapping Model & Deobfuscation Architecture

## 1. The Three-Layer Name Model

Minecraft 1.12.2 code exists across three distinct naming layers:

```text
┌────────────────────────────────────────────────────────┐
│ 1. Obfuscated / Notch Names (Mojang ProGuard Output)   │
│    Classes: a, b, c, amu, blc                          │
│    Fields:  a, b, c                                    │
│    Methods: a(), b()                                   │
└───────────────────────────▲────────────────────────────┘
                            │ (SRG mapping table / mcp.srg)
┌───────────────────────────▼────────────────────────────┐
│ 2. SRG / Searge Names (Stable Runtime Bytecode Names)  │
│    Classes: net.minecraft.world.WorldServer            │
│    Fields:  field_73068_V                              │
│    Methods: func_72835_b                               │
└───────────────────────────▲────────────────────────────┘
                            │ (MCP CSV tables: fields.csv, methods.csv)
┌───────────────────────────▼────────────────────────────┐
│ 3. MCP / Mapped Names (Human-Readable Development)     │
│    Classes: net.minecraft.world.WorldServer            │
│    Fields:  allPlayersSleeping                         │
│    Methods: tick                                       │
└────────────────────────────────────────────────────────┘
```

## 2. Layer Definitions & Roles

### A. Obfuscated (Notch) Names
- Generated by Mojang when building the production client/server jars with ProGuard.
- Completely unstable across minor releases.
- In 1.12.2 dedicated server jar, root package contains raw single/double letter identifiers (`net.minecraft.server.MinecraftServer` is partially unobfuscated in server jar, but internal world/entity classes are obfuscated, e.g. `amu`).

### B. Searge (SRG) Names
- Developed by the Mod Coder Pack (MCP) team to establish deterministic, stable identifiers.
- Format:
  - Class: Fully qualified package and class name (e.g. `net/minecraft/world/WorldServer`).
  - Method: `func_<id>_<suffix>` (e.g. `func_72835_b`).
  - Field: `field_<id>_<suffix>` (e.g. `field_73068_V`).
  - Parameter: `p_<id>_<param_index>_` (e.g. `p_72835_1_`).
- **Critical Runtime Invariant:** Compiled Forge mod `.jar` files in the wild are compiled against **SRG names**, NOT human-readable MCP names.
- When running in production, Forge's `DeobfuscationTransformer` translates runtime bytecode to SRG identifiers so mods can invoke vanilla methods.

### C. MCP (Mapped) Names
- Community-contributed English names assigned to SRG identifiers.
- Provided as CSV tables:
  - `fields.csv`: `searge,name,side,desc`
  - `methods.csv`: `searge,name,side,desc`
  - `params.csv`: `param,name,side`
- Local copy in repository: `third_party_reference/mappings/export/` (pinned to `stable_39-1.12`).
- Mod developers write Java against mapped names. ForgeGradle's `reobfJar` task translates mapped names back to SRG names at compile time.

## 3. How Other Systems Target Identifiers

| Subsystem | Naming Layer Used | Example |
|---|---|---|
| **Access Transformers (`accesstransformer.cfg`)** | SRG names | `public net.minecraft.world.WorldServer field_73068_V # allPlayersSleeping` |
| **Reflection in Mods** | Dual MCP + SRG fallback | `ReflectionHelper.findMethod(WorldServer.class, "tick", "func_72835_b")` |
| **Mixin / ASM Bytecode Hooks** | Obfuscated or SRG names | `@Inject(method = "func_72835_b", at = @At("HEAD"))` |
| **Crash Reports / Stack Traces** | SRG or Obfuscated | `at net.minecraft.world.WorldServer.func_72835_b(WorldServer.java:234)` |
| **Our Rust Core Engine** | Mapped / Canonical concepts | Translates to `WorldServer::tick()` |

## 4. Resolution Rules for RustCraft Research
When investigating bug reports, mod decompilations, or stack traces:
1. If an identifier starts with `func_`, search `third_party_reference/mappings/export/methods.csv` to find its human-readable MCP name and documentation.
2. If an identifier starts with `field_`, search `third_party_reference/mappings/export/fields.csv`.
3. If an identifier is a raw obfuscated name (e.g. `amu.a`), consult the SRG translation table to resolve class and member.
4. When writing parity tests and Rust FFI bridge contracts, always document BOTH the human MCP name AND the SRG identifier so future analysis can cross-reference mod coremods unambiguously.
