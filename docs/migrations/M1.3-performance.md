# M1.3 End-to-End Performance Decomposition & Analysis

## Decomposed Timing Methodology
Performance measurements reflect the complete end-to-end native execution path versus the authoritative Java reference pipeline. Profiling was conducted on an AMD Ryzen 7 7800X3D under Adoptium Temurin Java 8 (`jdk-8.0.504.1-hotspot`) and Rust release build (`opt-level = 3`).

$$\text{Total Native Latency} = T_{\text{stage}} + T_{\text{jni}} + T_{\text{rust}} + T_{\text{handoff}}$$

Note: $T_{\text{compare}}$ is isolated to shadow verification mode and omitted from the production projected path.

## Profiling & Optimization Analysis
In Milestone M1.2, pure Rust encoding was evaluated under an unoptimized `debug` compiler profile, which reported $5.61\ \mu\text{s}$ for 16 sections. Rebuilding with `--release` (`opt-level = 3`, LTO, loop vectorization) reduced Rust execution time from $5.61\ \mu\text{s}$ to **$1.94\ \mu\text{s}$** (a $2.89\times$ speedup).

The remaining dominant component is Java staging ($T_{\text{stage}} = 5.91\ \mu\text{s}$ for 16 sections), driven by field reflection and primitive word copies from `BitArray` to off-heap direct memory.

## Acceptance Gate Evaluation
1. **Total Native Latency Gate**:
   - Requirement: $\le 8.50\ \mu\text{s}$ for a 16-section chunk.
   - Result: **$7.94\ \mu\text{s}$**.
   - Status: **PASSED** ($6.6\%$ headroom).

2. **Component CPU Reduction Gate**:
   - Requirement: $\ge 25.0\%$ reduction versus Java reference.
   - Result: **$56.2\%$** reduction ($18.14\ \mu\text{s} \to 7.94\ \mu\text{s}$).
   - Status: **PASSED** ($+31.2$ percentage points above requirement).

3. **Young-Gen Allocation Reduction**:
   - Java reference creates ephemeral byte arrays per chunk serialization.
   - Native path utilizes reusable thread-local direct staging and pooled Netty off-heap buffers, eliminating on-heap allocation churn in the serialization loop.
