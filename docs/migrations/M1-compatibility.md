# M1 Compatibility Assessment: Forge, CoreMods & Modpack Ecosystem

## 1. Compatibility Mandate
Target Minecraft 1.12.2 and Forge 14.23.5.2860 with full support for large existing modpacks. Any migration that breaks modded block states, CoreMod transformers, or client network compatibility violates Permanent Invariant 3.

## 3. Block State & TileEntity Compatibility

### 3.1 16-Bit BlockState Registry
In Minecraft 1.12.2, all block states are registered in `Block.BLOCK_STATE_IDS` (`ObjectIntIdentityMap<IBlockState>`).
- Block states are identified by a 16-bit integer: $\text{ID} = (\text{BlockId} \ll 4) \mid (\text{Meta} \ \& \ 15)$.
- Forge supports modded block IDs up to 4,095.
- The native packet encoder treats these IDs as opaque numerical values, faithfully replicating the dynamic palette generation of Protocol 340.

### 3.2 TileEntity Synchronization Invariant
- **Rule**: `SPacketChunkData` includes a trailing `List<NBTTagCompound>` containing the update tags of all ticking TileEntities within the chunk.
- **Contract**: Mod TileEntities frequently override `getUpdateTag()` to transmit custom synchronization data (e.g. Ender IO conduit fluid levels, AE2 terminal channel states).
- **Boundary**: M1 does **NOT** serialize TileEntities in native code. TileEntity update tags are generated by Java mod code on the JVM, collected into the packet's Java list, and transmitted according to standard Forge network semantics.
