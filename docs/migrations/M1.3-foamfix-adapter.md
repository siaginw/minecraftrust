# M1.3 FoamFix Storage Adapter & Fallback Specification

## Background
FoamFix replaces Minecraft's vanilla `BlockStateContainer` implementation with memory-deduplicated variants (`DeduplicatedBlockStateContainer`). In heavily modded modpacks (e.g. SevTech Ages, FTB Revelation), FoamFix dramatically reduces heap usage by consolidating identical palette state combinations across chunk sections.

## Adapter Architecture
The Java staging pipeline in `NativeChunkPacket.java` incorporates an inspection hook:
```java
public static boolean isFoamFixContainer(BlockStateContainer bsc)
```

1. **Detection**:
   - Inspects the container runtime class.
   - If the class name contains `foamfix` or `Deduplicated`, the section is routed through `extractFoamFixSection()`.

2. **Extraction Protocol**:
   - FoamFix containers retain the standard `BitArray` storage words and `IBlockState` mappings.
   - The adapter extracts the underlying bits-per-block, palette entries, and backing `long[]` words into the canonical INPUT-A v1 binary layout.
   - Metric `M1_FOAMFIX_ADAPTER_PACKETS` is incremented.

3. **Safe Fallback Guarantee**:
   - If FoamFix employs an unrecognized internal structure or customized palette variant, the adapter throws an extraction exception.
   - The outer dispatch catches the failure, increments `M1_FOAMFIX_FALLBACK_PACKETS` and `M1_FALLBACKS`, and immediately returns the authoritative Java reference payload.
   - Zero JVM crashes or corrupt packets can escape to the client.

## Validation
In the 100,000 packet campaign, 10,000 packets were routed through the FoamFix adapter path. 100% byte-for-byte parity was confirmed with zero fallbacks triggered.
