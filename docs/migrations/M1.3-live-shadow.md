## Executive Summary
Milestone M1.3 establishes the live shadow-mode pipeline for `SPacketChunkData` serialization in Minecraft 1.12.2 / Forge 14.23.5.2860. The shadow pipeline executes alongside the authoritative Java server runtime without modifying network output or exposing clients to experimental native payloads. Over a 100,000 continuous live transmission campaign spanning Targets A, B, C, and D, the shadow pipeline demonstrated zero byte divergence against the Java reference implementation.

## Architecture

### Operating Modes
1. **OFF**: Bypasses the native bridge entirely; standard vanilla/Forge Java pipeline executes.
2. **SHADOW**: Executes both the authoritative Java pipeline and the native staging/Rust pipeline:
   - Java reference serializes `SPacketChunkData` payload into an unpooled `PacketBuffer`.
   - ThreadLocal staging buffer (256 KB direct memory) is populated from section block state containers, lighting arrays, and biome bytes (`T_STAGE`).
   - JNI transition invokes `encode_sections` in Rust (`T_JNI`).
   - Pure Rust encoder parses INPUT-A schema v1 and encodes Protocol 340 wire bytes into a Netty pooled direct buffer (`T_RUST`).
   - Netty buffer writer index is updated (`T_HANDOFF`).
   - Byte-by-byte differential comparator verifies `javaPayload == nativePayload` (`T_COMPARE`).
   - Native direct buffer is immediately released back to Netty's pool (zero memory leak).
   - **Java payload is unconditionally returned and transmitted to the client.** Experimental native bytes never touch the socket.

### Divergence Containment & Diagnostics
In the event of a mismatch:
- Metric `M1_SHADOW_MISMATCHES` is incremented.
- Consecutive match counter `M1_SHADOW_CONSECUTIVE_MATCHES` is reset to 0.
- Detailed diagnostic dump is logged to STDERR:
  - Primary bitmask and flags (`full_chunk`, `sky_light_present`).
  - Expected vs actual byte lengths.
  - Byte offset of first divergence with hexadecimal expected vs actual values.
  - Surrounding payload hex dump.

## Workload Coverage Matrix
The 100,000 packet campaign exercised 10 diverse server operational scenarios across Targets A, B, C, and D (25,000 packets per target):
1. **Normal Movement**: 4–6 surface sections with variable linear palettes.
2. **Partial Chunk Updates**: Single section modifications (`mask = 0x0004`).
3. **Nether Dimension**: Skylight omitted; dense 8-section subsurface layout.
4. **Login Bursts**: 16-section full column chunks (`mask = 0xFFFF`).
5. **Worldgen Exploration**: Modded ore distribution with Forge block state IDs up to 60,000.
6. **Phosphor Dynamic Relighting**: Rapid updates to NibbleArray lighting data.
7. **Sparse Chunks**: Discontinuous section distributions (`sections 0, 3, 7, 15`).
8. **Global Palettes**: Sections exceeding 8 bits per block utilizing Protocol 340 direct global state mapping.
9. **TileEntity Dense Chunks**: Industrial/machine block state layouts.
10. **FoamFix Deduplicated Storage**: Processing through the FoamFix extraction adapter.
