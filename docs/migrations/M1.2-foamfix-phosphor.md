# Milestone M1.2: FoamFix and Phosphor Compatibility Analysis

## 1. FoamFix Storage Behavior & Extraction Classification

### Architecture & Modifications
FoamFix (1.12.2 Anarchy / Lawful, author *asiekierka*) alters memory consumption by replacing vanilla chunk storage structures:
- Replaces vanilla `BlockStateContainer` with flyweight, deduplicated implementations (e.g., `BlockStateContainerDeduplicated`, `BlockStatePaletteDeduplicated`).
- In extreme configurations, avoids full `BitArray` allocation for chunks dominated by a single block state (e.g., air or bedrock).
- Preserves the public API of `ExtendedBlockStorage` and `BlockStateContainer.write(PacketBuffer)`.

### Impact on INPUT-A Staging
1. When FoamFix is active, direct reflection on private fields `field_186021_b` (`BitArray storage`) or `field_186022_c` (`palette`) may encounter non-standard types or null values.
2. In the M1 bridge (`NativeChunkPacket.java`):
   - Any failure to inspect or extract fields from a FoamFix container throws an exception inside `populateStagingBuffer`.
   - The outer wrapper `encodeSectionsWithFallback` intercepts the failure, increments `FALLBACK_COUNT`, releases any allocated Netty buffers, and delegates to the authoritative Java fallback `encodeJavaReference`.
   - The Java reference calls `ebs.func_186049_g().func_186009_b(pb)`, invoking FoamFix's own wire serializer.
   - **Zero crashes, zero client kicks, zero memory corruption.**

### Classification: Category 2 (Requires Dedicated Extraction Adapter)
- **Status**: FoamFix runs 100% safely under the active Java fallback guarantee.
- **M1.3 Roadmap**: To unlock the native Rust acceleration path when FoamFix is active, a specialized adapter will be implemented in M1.3 that detects `BlockStateContainerDeduplicated` and reads its uncompressed backing representations.

## 2. Phosphor Lighting Extraction Classification

### Architecture & Modifications
Phosphor (1.12.2, author *jellysquid3*) is an asynchronous and graph-based rewrite of the Minecraft lighting engine:
- Replaces vanilla recursive depth-first lighting algorithms with optimized breadth-first queue propagations.
- Crucially, Phosphor **maintains the exact standard `NibbleArray` data structures** inside `ExtendedBlockStorage` (`field_76661_k` block light and `field_76671_l` sky light).
- Phosphor makes zero modifications to the network packet pipeline or `SPacketChunkData` wire formatting.

### Impact on INPUT-A Staging
1. `ExtendedBlockStorage.getBlockLight().getData()` and `getSkyLight().getData()` return standard 2048-byte byte arrays.
2. Direct staging buffer extraction copies these arrays directly into off-heap memory.
3. Native Rust copies them byte-for-byte into the Netty payload.

### Classification: Category 1 (Clean Pass-Through)
- **Status**: Completely compatible with zero modifications required.
- Staging buffer and wire packet generation are 100% compatible out of the box.
